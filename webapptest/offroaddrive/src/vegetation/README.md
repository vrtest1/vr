# VegetationEngine

草と木。地面のどこに何が生えるかは、渡された「地面の情報」から決めます。

![岸辺の森（high プリセット）](../../docs/images/vegetation.png)

- デモ: `examples/vegetation/`（全部入り）　最小サンプル: `examples/vegetation/minimal.html`（平らな床だけで動く例）　木の見本: `examples/vegetation/trees.html`
- 依存: three.js（r170 で確認）、`src/core/`

## 仕組み

### 草

- 葉身 1 枚を 1 インスタンスとして、ドローコール 1〜2 回で描きます。位置・向き・高さ・しなり・風の揺れ・色は、すべて頂点シェーダで決めます。CPU は 1 本ごとの処理を一切しません。
- カメラ中心の正方格子を世界座標で巻き戻しているので、カメラを動かしても草は地面に固定されたままです。草 1 本の性質は世界の格子点から決まるため、同じ場所に戻れば同じ草が生えています。
- 近景（密）と遠景（まばらで幅広）の 2 枚に分け、境目と外周は本数を間引いて切り替えます。
- 風は `WorldEnvironment` の風向・風速に従い、一定の傾き + 草原を渡る突風の波 + 細かいはためきでなびきます。
- 光は海と同じくシーンの光源（太陽と空）と影をそのまま使います。逆光では葉が透けて明るくなります。

### 木

![樹種の見本。左からトウヒ、マツ、ナラ、シラカバ、低木、枯れ木](../../docs/images/trees.png)

**形**（`treeGeometry.js`）

- 幹から枝を再帰的に分岐させて骨組みを作り、枝は先細りの筒、葉は外側の小枝に付けた「葉のカード」（葉の房を描いたテクスチャを貼った板）にします。
- 樹種は 6 つ: トウヒ（円錐形の針葉樹）、マツ（幹の上部に傘状の樹冠）、ナラ（低い位置で大枝に分かれる広葉樹）、シラカバ（白い幹、細く垂れる枝）、低木、枯れ木。低木と枯れ木以外は、形の違う個体を 2 本ずつ持ちます（合計 10 モデル）。
- 葉のテクスチャ（`leafAtlas.js`）は起動時に Canvas 2D で描きます。画像ファイルは使いません。色は頂点カラーで付け、テクスチャは明暗だけを持ちます。
- 葉の法線は板の向きではなく、樹冠の中心から外へ向かう向きにしてあります。樹冠全体が 1 つの丸いかたまりとして陰影が付きます。樹冠の内側ほど暗い色にしてあります。
- 樹皮の模様（縦の筋、シラカバの横縞）はフラグメントシェーダで作ります。

**描き方: 距離で 3 段階**

| 段階 | 内容 | 既定の距離（high） |
|---|---|---|
| 近景メッシュ | 枝すべて + 葉のカード。1 本あたり 700〜4100 三角形 | 〜110 m |
| 軽いメッシュ | 幹と大枝 + 大きめの葉のカード。同じ木の骨組みから作るので形が一致。180〜510 三角形 | 〜340 m |
| ビルボード | 木を横と真上から焼き込んだ画像を貼った板 2 枚（4 三角形） | 〜2000 m |

- 段階は**木 1 本ごと**に距離で決まります。切り替えの手前 20% の区間では、2 つの段階を網点（ディザ）で混ぜます。片方が描かない画素をもう片方が必ず描く相補的な模様なので、穴は開きません。
- ビルボードの画像は、起動時に近景メッシュそのものをレンダリングして作ります（色と法線の 2 枚）。法線も焼き込むので、太陽の向きに応じてメッシュと同じ式で陰影が付きます。横向きの板はカメラの方を向き、見下ろす角度が急になると、真上から見た板に入れ替わります。
- 新しく生えた木は 1.2 秒かけて網点で現れます。描画範囲の端でも距離で薄れるので、移動中に森がまとめて現れることはありません。
- 風: 木全体のしなり + 枝の上下 + 葉のはためき。影にも反映されます。

**配置**

- CPU で配置します。320 m 角の区画（チャンク）ごとに、1 フレームに 1 区画ずつ、近い順に決めます。
- 生える条件: 植生のある場所、急斜面でない、寒すぎず暑すぎない、湿っているほど多い、水際から離れている。さらに粗い乱数の場で「森のかたまり」を作ります。
- 樹種は気温と湿り気で決めます。寒い場所はトウヒ、温暖な場所はナラ、乾いた場所はマツ、その間にシラカバ。別の乱数の場で同じ樹種がまとまって生えるようにしています。枯れ木は 1.5% ほど混ざります。
- 低木は、木が生えなかった候補点に低い確率で生えます。森の縁で多くなります。

## API

```js
const vegetation = new VegetationEngine({
  environment,
  quality: 'high',
  ground: terrain.getGroundShader(),                        // 草用（GPU）
  sample: (x, z, out) => terrain.getBiomeAt(x, z, out),     // 木用（CPU）
});
await vegetation.init(renderer);                               // 省略可（下記）
vegetation.addTo(scene);
for (const m of vegetation.materials) atmosphere.applyTo(m);   // 空気遠近などを付ける場合
vegetation.update(deltaTime, camera);                          // 毎フレーム
```

`init(renderer)` はビルボードの焼き込みに使うレンダラーを渡します。省略した場合は、最初に描画されたフレームからレンダラーを受け取り、次の `update()` で焼き込みます（それまでの 1〜2 フレームは遠くの木が出ません）。`World.add()` を使う場合は自動で呼ばれます。

地面の情報は 2 つあり、どちらも省略できます（省略すると高さ `groundY` の平面に一様に生えます）。

| オプション | 形式 | 内容 |
|---|---|---|
| `ground` | `{ glsl, uniforms }` | GLSL で `vec3 pwvGroundHeight(vec2 xz)`（高さ, 勾配 x, 勾配 z）と `vec2 pwvGroundInfo(vec3 pos, vec3 normal)`（生えやすさ 0–1, 乾燥度 0–1）を定義 |
| `sample` | `(x, z, out) => out` | `out` に `height / slope / vegetation / moisture / temperature` を入れて返す（`slope` は 1 − 法線の y） |
| `groundY` | number | 上の 2 つを省略したときの平面の高さ |

TerrainEngine を使わない場合も、同じ形式で自前の地面を渡せます。

| メンバー | 意味 |
|---|---|
| `materials` | このエンジンの全マテリアル（草 1〜2 枚 + 木 3 枚）。`applyTo` 系に渡す用 |
| `getCoverShader()` | 生えているものの色を GLSL として取り出す。`terrain.setCover(vegetation.getCoverShader())` と渡すと、草の下の地面が草の根元と同じ色になり、草や木が描かれない遠くの地面にも草原と森の色が続く |
| `grassMaterials` / `treeMaterials` | 個別に取り出す場合。`treeMaterials` は [軽いメッシュ, 近景メッシュ, ビルボード] |
| `treeModels` | 使っている木のモデル一覧（`species / seed / height / radius`） |

### 木だけを使う

エンジンを使わず、木の形だけを普通の three.js のメッシュとして使えます（`examples/vegetation/trees.html`）。

```js
import { createTree, createTreeMaterial, createLeafAtlas, TREE_SPECIES } from './src/index.js';

const material = createTreeMaterial(createLeafAtlas());       // 全樹種で共用
const oak = new THREE.Mesh(createTree('oak', { seed: 3 }), material);
```

| 関数 | 内容 |
|---|---|
| `TREE_SPECIES` | 樹種名の配列: `spruce / pine / oak / birch / bush / snag` |
| `createTree(species, { detail, seed })` | 木のジオメトリ。`detail` は 2 = 近景用、1 = 軽い形。`seed` で個体が変わる |
| `buildTreeModel(species, seed)` | 両方の細かさの頂点データと、高さ・半径・葉の平均色 |
| `createTreeGeometry(data)` | `buildTreeModel()` の `near` / `mid` をジオメトリにする |
| `createLeafAtlas(cellSize)` | 葉のテクスチャ（4 × 2 マス、既定は 1 マス 256 px） |
| `createTreeMaterial(leafAtlas)` | 木用の MeshLambertMaterial（アルファ抜き、両面、頂点カラー） |

### パラメータ

| 名前 | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| `grass` | true | — | 草の表示 |
| `grassDensity` | 1 | 0–1 | 草の密度 |
| `grassHeight` | 0.5 | 0.05–2 | 草の高さ（m） |
| `grassWidth` | 0.04 | 0.005–0.2 | 葉の幅（m） |
| `grassColor` / `dryGrassColor` | `#4f7a2c` / `#8f8650` | 色 | 湿った場所 / 乾いた場所の草の色（地形の地面の色と揃えてある） |
| `trees` | true | — | 木の表示 |
| `treeDensity` | 1 | 0–2 | 木の密度（変更すると配置し直す） |
| `bushDensity` | 1 | 0–3 | 低木の密度（変更すると配置し直す） |
| `treeScale` | 1 | 0.3–3 | 木の大きさ（変更すると配置し直す） |
| `canopyColor` | `#2c4a1c` | 色 | 木が描かれない遠くで、森のある地面に付く色（`getCoverShader()` を地形に渡したとき） |
| `lodScale` | 1 | 0.3–2 | メッシュで描く距離の倍率。下げると軽くなり、ビルボードに早く切り替わる |
| `castShadow` | true | — | メッシュの木が影を落とす |
| `wind` | 1 | 0–3 | 風への反応の強さ |
| `seed` | 1 | 0–9999 | 木の配置の種（変更すると配置し直す） |

## パフォーマンス実測

Apple M4 Max、Chrome（ヘッドレス、ANGLE Metal）、1280×720、全エンジン入りのデモで岸辺の森（デモの開始位置）。2026-11-13 計測。

| プリセット | FPS | GPU 時間（全エンジン合計） | CPU 時間 | ドローコール | 三角形 | 木（全体） | 近景 / 軽いメッシュ |
|---|---|---|---|---|---|---|---|
| ultra | 60（上限） | 14.7 ms | 0.2 ms | 116 | 1176 万 | 11.0 万本 | 403 / 2146 本 |
| high | 60（上限） | 9.9〜12.1 ms | 1.4 ms | 86 | 568 万 | 5.7 万本 | 214 / 1324 本 |
| medium | 60（上限） | 7.0 ms | 1.2 ms | 51 | 165 万 | 1.5 万本 | 63 / 449 本 |
| low | 60（上限） | 3.4 ms | 0.8 ms | 30 | 31 万 | 0.5 万本 | 17 / 132 本 |

- GPU 時間は実行ごとに 2 ms ほど揺れます（high は 3 回の計測で 9.9 / 10.1 / 12.1 ms）。様式化された木だった以前の版は ultra 14.0 / high 11.1 / medium 6.3 / low 3.4 ms だったので、同程度です。
- 同じ実行内で草と木をすべて消すと high は 12.1 → 8.0 ms でした。植生の分は約 4 ms です。
- 木の区画 1 つの生成は平均 2.5 ms、最大 5.3 ms（high、CPU）。起動後や品質変更後は、全区画が揃うまで約 3〜5 秒、毎フレーム 1 区画ずつ生成します。
- 近くの木の一覧は、カメラが 4 m 動くたびに作り直します。歩行中の `update()` は中央値 0.2 ms で、区画の生成が重なったフレームだけ 5 ms 台になりました。
- **対数深度バッファとの組み合わせ。** デモは遠景の精度のために `logarithmicDepthBuffer` を使っています。three.js はこのとき全画素の深度をフラグメントシェーダで書くため、GPU が「隠れた画素を先に捨てる」処理を使えなくなり、葉が何層にも重なる森では ultra が 42 ms まで落ちました。木と草は三角形が小さいので、同じ深度を頂点シェーダで設定する方式に変え、近い木から順に描くようにして 14.7 ms に戻しています。
- ultra の 14.7 ms は 60fps の予算に近く、解像度が上がると落ちる可能性があります。**iPhone と Quest 3 では未計測です。**

## 既知の制限

- **遠くの森は地面の色。** 木を描く距離（`treeRange`）より先は、森のある場所の地面を濃い緑にしているだけで、木の形はありません。境目では木が 1 本ずつ消えていきます。`getCoverShader()` を地形に渡していない場合、遠くの地面は草原の色のままです。
- **地面の色合わせは TerrainEngine との組み合わせ用。** `setCover` に相当する口を持たない地面では、草の根元と地面の色は合いません。

- **木は手続き生成の様式化された形。** 枝と葉はありますが、葉は 1 枚ずつではなく房を描いた板です。近くで見ると板であることが分かります。写真のような木ではありません。
- **同じ形の木が並ぶ。** モデルは 10 本だけです。向き・大きさ・色合いを 1 本ごとに変えていますが、よく見ると同じ個体が見つかります。
- **切り替え区間の網点が見える。** 段階を混ぜている区間の木は、拡大すると点々の模様が見えます。
- **ビルボードは影を落とさない。** 軽いメッシュより遠い木の影は地面に出ません（影は受けます）。medium は近景メッシュの外、low はすべての木で影が落ちません。
- **ビルボードは 1 方向から見た絵。** 遠くの木は、回り込んでも同じ面が見えます（左右反転で 2 通り）。真横と真上の 2 枚なので、斜め上から見ると板が交差して見えることがあります。
- **カメラのごく近くで前後関係がずれることがある。** 深度を頂点ごとに設定しているため、カメラから 1 m 以内にある幹や葉では、すぐ後ろの草が手前に描かれることがあります（対数深度バッファ使用時のみ）。
- **草は木の下や岩の上にも生える。** 木の位置は草に伝えていません。岩場・雪・砂浜は地面の情報（生えやすさ）で除外されます。
- **草の影は受けるだけ。** 草は影を落としません。草どうしの遮蔽は根元を暗くすることで近似しています。
- **草が生えるのは近くだけ。** その先は地面の色で代用します（色は揃えてありますが、近づくと草が「生えてくる」のが見えます）。高空からは草は見えません。
- **草の頂点ごとに地面の高さを計算する。** 地形の高さ関数を葉の全頂点で評価するため、草の枠数に比例して頂点処理が重くなります（視界の外の枠も計算されます）。
- **木に当たり判定がない。** 踏んでも倒れず、カメラは幹をすり抜けます。
- **季節がない。** 落葉、紅葉、積雪した木はありません。草の色は湿り気と寒さで変わるだけです。
- **近くの木は視界の外でも頂点処理される。** メッシュの木はカメラの周囲全体を 1 回のドローコールで描くため、背後の木も頂点シェーダを通ります。
- **three のバージョン依存。** 草とビルボードはライト・影・フォグのシェーダチャンクを、木のメッシュは MeshLambertMaterial と MeshDepthMaterial の `begin_vertex` / `beginnormal_vertex` / `project_vertex` / `logdepthbuf_*` / `map_fragment` / `normal_fragment_begin` / `lights_fragment_end` を書き換えています。r170 で確認。
- **ブラウザ専用。** 葉のテクスチャに Canvas 2D（`document`）を使います。
