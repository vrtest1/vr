# PostProcessEngine

フレームの最後の工程です。シーンを画面の外の絵に描いてから、露出・トーンマッピング・色調補正を 1 回だけ掛けて画面に出します。ブルーム、ビネット、ディザリング、水に関する画面効果、内部解像度の引き下げと拡大もここで行います。

![夕方の太陽とブルーム、ビネット（high プリセット、全エンジン）](../../docs/images/postprocess.png)

![水面をまたぐ途中の画面](../../docs/images/postprocess-waterline.png)

- デモ: `examples/postprocess/`（全エンジン。`?post=0` でオフの状態から始まる）　最小サンプル: `examples/postprocess/minimal.html`（ほかのエンジンなしで動く例）
- 依存: three.js（r170 で確認）、`src/core/`

## 組み込み方

`renderer.render(scene, camera)` の代わりに `post.render(scene, camera)` を呼びます。変更はこの 1 行だけです。

```js
const post = new PostProcessEngine({
  environment,
  quality: 'high',
  waterDepth: () => underwater.depth,   // 省略可。カメラの水深（m、水上は負）。省略すると水の効果なし
});
await post.init(renderer);              // World.add なら自動
// ループ内
post.update(deltaTime, camera);         // World.update なら自動
post.render(scene, camera);
```

- `init(renderer)` のとき、パラメータで指定していない `toneMapping` と `exposure` はレンダラーの現在の設定を引き継ぎます。エンジンを足しただけでは見た目が変わりません。
- `render()` は呼び出しのあいだだけレンダラーの `toneMapping` と `toneMappingExposure` をパラメータの値にし、終わったら元に戻します。露出とトーンマッピングは、以後このエンジンのパラメータで変えてください。
- キャンバスは `antialias: true` のままで構いません（WebXR ではその設定が使われます）。

| メンバー | 意味 |
|---|---|
| `render(scene, camera)` | シーンを描く。`renderer.render` の代わり |
| `active` | 直近の `render()` がポストプロセスを通ったか |
| `effectiveScale` | 実際の内部解像度の割合（プリセットの倍率 × `renderScale`） |
| `getStats()` | `mode`（`post` / `direct (off)` / `direct (xr)` / `direct (unsupported)`）、内部解像度、パス数、ブルームの段数 |

## 1 フレームの流れ

1. **各エンジンの `update()`** — 大気の LUT と雲、霧の格子など、それぞれが自分の絵を用意します。
2. **シーンを描く** — 線形の光のまま（HDR、16 bit 浮動小数、MSAA つき）で内部解像度の絵に描きます。マテリアルの中の順序はこれまでどおり「面の色 → 大気の空気遠近 → 霧 → 水中」で、そのあと空、空の前の霧、煙が描かれます。
3. **ブルーム** — 明るすぎる部分だけを取り出し、半分の大きさに何度も縮めてから足し戻します。
4. **合成** — 水中のゆらぎ、水面の境界線、ブルームの加算、ホワイトバランス、露出とトーンマッピング、sRGB への変換、彩度とコントラスト、ビネット。
5. **拡大** — 内部解像度が画面より小さいときだけ。輪郭に沿って引き伸ばします（EASU）。
6. **シャープ化** — 拡大したときだけ（RCAS）。
7. **ディザリング** — 最後のパスで、8 bit に丸める直前に加えます。

### トーンマッピングが二重にならない理由

three は、レンダーターゲットに描くときは各マテリアルのトーンマッピングと sRGB 変換を自動で外します。これまでのエンジンのシェーダは three の `tonemapping_fragment` / `colorspace_fragment` をそのまま使っているので、手を入れなくても 2 の絵は線形のままになり、トーンマッピングは 4 の 1 回だけです。合成のシェーダは three 自身のトーンマッピング関数を使うので、オンとオフで同じ曲線になります。

### 水の効果と UnderwaterEngine の分担

- 水の色への溶け込み、深さによる減光、コースティクス、光芒は UnderwaterEngine がシーンの中で行います。**このエンジンは水中にいるあいだ、それらを一切足しません。足すのは画面のゆらぎだけです。**
- シーンは「全体が水上」か「全体が水中」のどちらかで描かれます。カメラが水面の `waterBand`（既定 0.3 m）以内まで近づくと、このエンジンが画面に水面の境界線を引き、線より下を水の色にします。線はカメラが下がるにつれて画面の下から上へ進み、カメラが水に入る瞬間に画面全体を覆います。そこでシーンが水中の描き方に切り替わり、このエンジンの水の色は消えます。水の色を足すのはカメラが水上にいるあいだだけなので、二重にはなりません。
- 境界線は水平線と平行で、カメラを傾けると一緒に傾きます。
- `waterDepth` に `() => underwater.depth` を渡せば、波に合わせて境界線が上下します。OceanEngine とは UnderwaterEngine の `waterHeight` を通じてつながります。

## パラメータ

| 名前 | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| `enabled` | true | | false でシーンを画面へ直接描く（比較用） |
| `toneMapping` | `aces`（init でレンダラーから引き継ぎ） | `linear / reinhard / cineon / aces / agx / neutral` | トーンマッピングの曲線 |
| `exposure` | 1（init でレンダラーから引き継ぎ） | 0.02–4 | 露出 |
| `saturation` | 1 | 0–2 | 彩度 |
| `contrast` | 1 | 0.5–1.5 | コントラスト |
| `temperature` | 0 | -1–1 | ホワイトバランス（負で青く、正で暖かく） |
| `tint` | 0 | -1–1 | ホワイトバランス（負で緑、正でマゼンタ） |
| `bloom` | true | | ブルーム |
| `bloomIntensity` | 0.3 | 0–3 | ブルームの強さ |
| `bloomThreshold` | 1.2 | 0–8 | これより明るい部分がにじむ（露出を掛けたあとの明るさ） |
| `bloomKnee` | 0.5 | 0–2 | しきい値の前後のなだらかさ |
| `bloomRadius` | 1 | 0.5–2 | にじみの広がり |
| `vignette` | 0.2 | 0–1 | 画面の四隅を暗くする強さ |
| `vignetteStart` | 0.55 | 0–1.3 | 暗くなり始める位置（0 = 中心、1 = 辺） |
| `dither` | true | | ディザリング |
| `waterEffects` | true | | 水の画面効果 |
| `distortion` | 1 | 0–3 | 水中のゆらぎの強さ |
| `waterBand` | 0.3 | 0.05–1.5 | 境界線が現れる、水面からの高さ（m） |
| `waterColor` | `#2a8fb0` | 色 | 境界線の下の水の色。UnderwaterEngine の `waterColor` と揃える |
| `renderScale` | 1 | 0.4–1 | 内部解像度の割合（縦横それぞれ） |
| `upscaler` | `fsr` | `fsr / bilinear` | 拡大の方法 |
| `sharpness` | 0.5 | 0–1 | 拡大したときのシャープ化の強さ |

ブルームは、太陽、水面の照り返し、`emissive` を 1 より大きくしたマテリアルなど、画面に出せる明るさを超えた部分に掛かります。

### 品質プリセット

| | ultra | high | medium | low |
|---|---|---|---|---|
| 内部解像度の倍率 | 1 | 1 | 0.85 | 0.7 |
| MSAA のサンプル数 | 4 | 4 | 4 | 2 |
| ブルームの段数 | 6 | 5 | 4 | なし |
| 輪郭に沿った拡大（EASU） | あり | あり | あり | なし（バイリニア） |

実際の内部解像度は「プリセットの倍率 × `renderScale`」です。シャープ化はどのプリセットでも、拡大したときに掛かります。

## アップスケーリング

- **EASU** — 周囲 12 画素から輪郭の向きと鋭さを調べ、輪郭に沿って伸ばした重みで補間します。
- **RCAS** — 上下左右の 4 画素との差を、白飛びや黒つぶれが起きない範囲で強調します。

どちらも AMD FidelityFX Super Resolution 1（MIT ライセンス）の公開されたアルゴリズムを、WebGL2 の GLSL として書いたものです。AMD のソースそのものではなく、公式の実装との出力の一致は確認していません。FSR 1 と同じく 1 枚の絵だけを使う空間的な拡大で、DLSS や FSR 2 以降のような時間方向の情報は使いません。

**時間方向のアップスケーリングは未実装です。** 入れる場合は合成（4）と拡大（5）のあいだに「前フレームの結果と混ぜる」パスを足す形になります。そのためには、画素ごとの動きの量（速度バッファ）、フレームごとのカメラの微小なずらし、シーンの奥行きのテクスチャが必要で、いずれも今はありません。

## WebXR

XR セッション中は `render()` がポストプロセスを通さず、シーンをヘッドセットのフレームバッファへ直接描きます（`getStats().mode` が `direct (xr)`）。トーンマッピングと露出はパラメータの値がそのまま使われるので、明るさと色は変わりません。ブルーム、ビネット、色調補正、水の画面効果、内部解像度の変更は XR 中は無効です。浮動小数のテクスチャに描けない端末でも同じ経路になります（`direct (unsupported)`）。

## パフォーマンス実測

Apple M4 Max、Chrome（ヘッドレス、ANGLE Metal）、1280×633、全エンジンのデモ。`examples/postprocess/` の岸辺で、アニメーションループを止めて 30 フレームを続けて描き、1 フレームあたりの所要時間を測りました（設定を交互に切り替えて 4 回、その平均）。

| プリセット | オフ（直接描画） | オン | オン・ブルームなし |
|---|---|---|---|
| ultra | 29.3 ms | 30.5 ms | 29.8 ms |
| high | 17.9 ms | 21.0 ms | 18.8 ms |
| medium（内部 0.85 倍） | 3.4 ms | 3.1 ms | 3.2 ms |
| low（内部 0.7 倍、ブルームなし） | 1.5 ms | 1.3 ms | 1.3 ms |

森の中（high）で内部解像度を変えた場合: オフ 10.2 ms、オン 9.9 ms、`renderScale` 0.77 で 9.0 ms、0.59 で 7.9 ms。

**この数字は絶対値としては当てになりません。** 計測したとき、同じマシンでほかのタブがデモを描いていて GPU を取り合っており、ポストプロセスなしの基準が、取り合いのないときの約 3 倍になっていました。同じ実行の中での比としては、high でオンにすると約 17 % 増（うちブルームが約 12 %）、内部解像度を 0.77 倍にすると基準より軽くなる、と読めます。ブラウザの GPU タイマー（デモの HUD の `GPU`）は取り合いの中ではパスの数に比例して大きく出たため、使っていません。**取り合いのない状態での再計測、iPhone と Quest 3 での計測はしていません。**

オンとオフの比較は、デモの GUI の `post-processing`、または `post.setParameters({ enabled: false })` で行えます。個別の効果も `bloom`、`renderScale`、`upscaler`、`sharpness`、`waterEffects` で切り替えられます。

## 既知の制限

- **XR 中は効果なし。** 上記のとおり、直接描画に切り替えます。
- **明るい輪郭にジャギーが残ることがある。** MSAA の平均を線形の光のまま取るので、太陽の照り返しのような極端に明るい画素が隣にあると、輪郭がなめらかになりきりません。
- **等倍ではシャープ化しない。** RCAS は内部解像度を下げたときだけ掛かります。
- **拡大は 1 枚の絵から。** 細い枝や草のような、内部解像度で消えた細部は戻りません。ちらつきも減りません。
- **水面の境界線は近似。** 線の下を水の色に寄せているだけで、線の下に本当の水中の景色（海底やコースティクス）は見えません。カメラが水に入る瞬間に、その色から本当の水中の描画へ切り替わります。カメラが真下を向いているときは線が出ず、画面全体が一度に切り替わります。水から出るときも同じ線が逆向きに動きますが、レンズを水滴が流れる表現はありません。
- **水中のゆらぎは画面全体に一様。** 距離による違いはなく、画面の端では弱めています。被写界深度やぼかしはありません。
- **奥行きを使う効果はない。** シーンの奥行きのテクスチャを作っていないので、被写界深度、スクリーンスペース反射、煙のソフトパーティクルは未実装です。
- **透明度は残らない。** 最終的な絵は不透明として扱います。ページの背景が透けるキャンバスには使えません。
- **最初のフレームでシェーダを作り直す。** レンダーターゲット用のシェーダは画面用と別なので、初めてオンにしたとき（とオフに戻したとき）に 1 回だけ引っかかりが出ます。
- **レンズフレア、色収差、フィルムグレイン、LUT による色変換はない。**
- **three のバージョン依存。** レンダーターゲットに描くときトーンマッピングと sRGB 変換が外れるという three の動作と、`tonemapping_pars_fragment` の関数名に依存しています。r170 で確認。
