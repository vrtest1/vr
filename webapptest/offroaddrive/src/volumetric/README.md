# VolumetricEngine

霧・光芒・煙を、ポストプロセスなしで既存のシーンに足します。

![朝霧の岸辺（high プリセット、全エンジン）](../../docs/images/volumetric.png)

![柱の影が霧の中に作る光芒と、煙（最小サンプル）](../../docs/images/volumetric-shafts.png)

- デモ: `examples/volumetric/`（地形 + 大気 + 海 + 水中 + 植生 + 霧 + 音）　最小サンプル: `examples/volumetric/minimal.html`（床と柱と太陽だけで動く例）
- 依存: three.js（r170 で確認）、`src/core/`

## 仕組み

- **霧** — `baseHeight` でいちばん濃く、上へ行くほど指数的に薄くなる水平な層です。`applyTo(material)` したマテリアルは、トーンマッピングの直前に「カメラからその点までの霧」を受けます。何も描かれなかった画素（空）には、エンジン自身が霧を重ねます。
- **霧の格子** — カメラの近く（`range` まで）の霧は、視野を粗く区切った格子の上で毎フレーム 1 回だけ計算します。格子の各マスは「カメラからそのマスまでの霧が足す光」と「霧を通り抜ける光の割合」を持ち、マテリアルはそれを 2 回のテクスチャ参照で読みます。画面上で物がどれだけ重なっても、霧の計算量は増えません。
- **むら** — 格子の計算のときに、風で流れる 3 次元ノイズで霧の濃さを変えます。
- **光芒** — 格子の計算のときに、太陽の影のマップを調べます。影の中の霧には太陽の光を足さないので、影と影のあいだが光の筋として残ります。
- **格子の外** — `range` より遠くと、格子がないとき（low プリセット、`init(renderer)` を呼んでいないとき）は、霧を式で積分します。霧の量はどのプリセットでも同じで、違うのはむらと光芒の有無だけです。
- **霧の明るさ** — 空の光の分は `WorldEnvironment` の空の色、太陽の分は `light` の色と強さから決めます。太陽の方向を見ると明るく、霧が濃いところでは奥まで光が届かず暗くなります。夜は暗くなります。
- **煙** — カメラを向く板（粒）の集まりです。粒は状態を持たず、時刻から年齢を、年齢から位置を頂点シェーダで求めます。上昇し、風下へ流れ、広がりながら消えます。霧の中では煙も霞みます。

## API

```js
const volumetric = new VolumetricEngine({
  environment,
  quality: 'high',
  light: sun,                              // 太陽の DirectionalLight。省略すると光芒なし
  submerged: () => underwater.submerged,   // 省略可。水中にいる間は空の前の霧を描かない
});
await volumetric.init(renderer);           // 霧の格子に必要（World.add なら自動）
volumetric.addTo(scene);
volumetric.applyTo(terrain.mesh.material);
volumetric.applyToObject(house);           // 配下の標準マテリアル全部
const smoke = volumetric.addSmoke({ position: new THREE.Vector3(0, 0.3, 0) });
volumetric.update(deltaTime, camera);      // 毎フレーム、描画の前
```

同じマテリアルに複数のエンジンの `applyTo` を使う場合は、**大気 → 霧 → 水中**の順に呼んでください。

| メンバー | 意味 |
|---|---|
| `applyTo(material, { grid })` | マテリアルを霧の中に置く。`grid: false` はなめらかな霧だけ（むらと光芒なし、テクスチャ参照なし） |
| `applyToObject(object3d, options)` | 配下の Standard / Lambert / Phong / Basic マテリアルすべてに `applyTo` |
| `removeFrom(material)` | 取り消し（`dispose()` 時は自動） |
| `addSmoke(options)` | 煙の発生源を足す（最大 8）。戻り値の `set({...})` で変更、`remove()` で削除 |
| `removeSmoke(handle)` / `smokes` | 発生源の削除 / 一覧 |
| `light` | 光芒に使う光源。後から差し替え可 |
| `createFogNoise(size, seed)` | むらと煙に使う、繰り返しのきく 3 次元ノイズのテクスチャを作る関数（別 export） |

### 煙のオプション

| 名前 | 既定値 | 意味 |
|---|---|---|
| `position` | （必須） | 発生源の位置 |
| `radius` | 1.2 | 発生源の大きさ（m） |
| `rise` | 2.5 | 上昇の速さ（m/s） |
| `life` | 16 | 粒が消えるまでの時間（秒） |
| `turbulence` | 1 | 粒のふらつきと広がり |
| `wind` | 1 | 風にどれだけ流されるか |
| `color` | `#8d8a86` | 煙の色（暗くすると黒煙、白くすると湯気） |
| `opacity` | 0.6 | 濃さ |

### パラメータ

| 名前 | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| `strength` | 1 | 0–2 | 霧全体の強さ（0 で無効） |
| `visibility` | 500 | 15–20000 | 霧のいちばん濃い高さでの見通し（m）。光が約 5 % まで減る距離 |
| `baseHeight` | 0 | -500–5000 | 霧がいちばん濃い高さ（`WorldEnvironment.waterLevel` からの m） |
| `falloff` | 40 | 2–2000 | 霧の厚み（m）。この高さごとに濃さが約 37 % になる |
| `humidityResponse` | 0.5 | 0–1 | 湿度への連動。湿度 55 % を基準に、高いほど濃く、低いほど薄くなる |
| `wisps` | 0.6 | 0–1 | むらの強さ |
| `wispSize` | 90 | 5–1000 | むらの大きさ（m） |
| `drift` | 1 | 0–4 | むらが風で流れる速さ |
| `tint` | `#ffffff` | 色 | 霧の色 |
| `brightness` | 1 | 0–4 | 霧の明るさ |
| `sunScatter` | 1 | 0–4 | 霧に入る太陽の光の強さ |
| `anisotropy` | 0.6 | 0–0.85 | 太陽の方向を見たときの輝きの強さ |
| `shafts` | 1 | 0–1 | 光芒の強さ（0 で影のマップを見ない） |
| `range` | 350 | 20–3000 | 格子が届く距離（m）。むらと光芒が出る範囲 |
| `smoke` | true | | 煙の表示 |
| `smokeOpacity` | 1 | 0–2 | すべての煙の濃さに掛ける値 |
| `timeScale` | 1 | 0–4 | 煙の動きの速さ |

### 品質プリセット

| | ultra | high | medium | low |
|---|---|---|---|---|
| 霧の格子（横 × 縦 × 奥行き） | 160 × 90 × 48 | 128 × 72 × 32 | 96 × 54 × 24 | なし |
| むらのノイズの層 | 2 | 2 | 1 | — |
| 煙の粒（発生源あたり） | 96 | 64 | 40 | 24 |

low では霧はなめらかになり、むらと光芒は出ません。霧の量と煙は同じです。

## パフォーマンス実測

Apple M4 Max、Chrome（ヘッドレス、ANGLE Metal）、1280×720、全エンジンのデモで森の中（木の葉が何重にも重なる、いちばん重い状況）。同じ実行の中で霧と煙をオン / オフして比べました。

| プリセット | FPS | GPU 時間（霧あり） | GPU 時間（霧なし） |
|---|---|---|---|
| ultra | 60（上限） | 19.5 ms | 18.3 ms |
| high | 60（上限） | 11.7 ms | 11.8 ms |
| medium | 60（上限） | 7.9 ms | 7.4 ms |
| low | 60（上限） | 3.8 ms | 3.6 ms |

計測のゆらぎは 1 ms 程度あります。霧による追加は、どのプリセットでもそのゆらぎと同じくらい（1 ms 以内）でした。**iPhone と Quest 3 では未計測です。**

最初の実装は、マテリアルごとに視線に沿って 10 回サンプルする方式でした。葉が重なる森の中では GPU 時間が約 20 ms 増えたため、格子の方式に作り直しています。

## 既知の制限

- **霧は水平な層。** 地形の起伏には沿いません。谷ごとに霧の高さを変えることや、霧の塊を置くことはできません。
- **光芒は影のマップが届く範囲だけ。** AtmosphereEngine の太陽の影は既定でカメラの周り 700 m です。遠くの山が作る大きな光芒（薄明光線）や、雲の影による光芒は出ません。
- **光芒の輪郭は粗い。** 格子の解像度（high で横 128 マス）で決まるので、細い影の筋はぼやけ、影の縁が階段状に見えることがあります。
- **光芒は 1 フレーム前の影を使う。** 霧の格子は描画の前に計算するので、影のマップは前のフレームのものです。カメラや太陽が速く動くと、光芒がわずかに遅れます。
- **VSM の影では光芒が出ない。** `renderer.shadowMap.type` が `VSMShadowMap` のときは、影のマップの形式が違うため光芒をオフにします。影そのものがオフのとき（既定の low）も同じです。
- **霧は地面に届く光を減らさない。** 濃い霧の中でも、地面や木の明るさと影の濃さは変わりません。
- **煙は粒の重ね描き。** 粒どうしの前後は並べ替えていません。物に重なるところでは粒の縁が直線で切れます（ソフトパーティクルは奥行きのテクスチャが必要なため未実装）。煙は影を落とさず、影を受けません。
- **煙に空気遠近は付かない。** 霧の中では霞みますが、AtmosphereEngine の `applyTo` には対応していません。遠くの煙は少し濃く見えます。
- **煙は風の変化に一斉に従う。** 粒が状態を持たないため、風向きが変わると煙全体が向きを変えます（急には変わらないよう、風にはゆっくり追従させています）。
- **空の前の霧は近似。** 何も描かれなかった画素には、トーンマッピング後の色どうしで霧を混ぜます。マテリアルに付く霧とは混ぜ方がわずかに違います。
- **WebXR は未検証。** 格子は `update()` に渡されたカメラ（XR では両目をまとめたカメラ）の視野で作る実装ですが、実機では確認していません。
- **`applyTo` していないマテリアルは霧の影響を受けない。** `ShaderMaterial` など独自シェーダには自動では付きません。
- **three のバージョン依存。** `fog_vertex` と `tonemapping_fragment` のチャンク名、影のマップの深度の詰め方（rgba）に依存しています。r170 で確認。
